# `rs44-capture-2026-09-02.csv` — what is actually in this file

**Its own verdict says `NOT PROVEN`, and that is the correct answer.** This note exists so
nobody later reads the file as a clean recording of the pass, because it is not one.

    RS-44, 2026-09-03 02:37:15Z AOS → 02:54:42Z LOS, peak 41.1°, II22TB
    2718 rows, 02:12:00Z → 02:58:00Z, logged by sat_capture.py at ~1 Hz

## Two things contaminate it, both avoidable, both mine

**1. The logger was started 25 minutes before AOS, while the radio was still parked on 2 m.**
8 samples sit at 145.0698 MHz and 2709 at 70 cm, so the file spans **290 MHz**. The magnitude
check compares the total sweep against the orbital Doppler bound (10.7 kHz here) and fails it —
correctly. A file containing two bands cannot be one pass.

**2. The operator tuned by hand during the pass.** Nigel was hunting for a voice inside the
60 kHz transponder passband while a driver was recentring the radio every second. The two
fought. **89 one-second steps exceed 500 Hz/s**, which no Doppler on this orbit can produce
(the real rate peaks near 30 Hz/s); the first is at **02:45:02Z**, around TCA. The radio's own
frequency reverses direction **60 times** across the pass window, where a real pass reverses
exactly **once**, at TCA.

That fight is the subject of [`../claude-memory`][offset] — the offset rule — and is fixed:
`drive_rx.py` and `tracker.py` now treat the operator's tuning as state to be kept, not error
to be corrected. A capture taken after that fix should be clean.

## What the file DOES support

Where neither problem applies, the tracking is good: across 813 clean samples the median
residual between the radio's own read-back and the Skyfield prediction is **18 Hz**. The shape
check passes — exactly one direction reversal in the predicted range rate, at TCA — and the
peak elevation matches at 41.1°. At closest approach the radio sat on **435.640037 MHz**
against a rest frequency of **435.640000 MHz**.

## What it does NOT support

- It is **not** evidence that two independent Doppler sources agree. Our own driver was
  stepping the radio for most of the pass, so it shows the radio obeys and the view reports
  truthfully. The independent check was 02:12–02:17Z, when Gpredict's numbers matched Skyfield
  to 1–2 Hz, before Gpredict died on a single rigctl `RPRT -8`.
- It is **not** a usable reference capture. Use it as an example of the failure modes, not as
  a baseline. `pass-RS44-2026-08-29.csv` is not one either — despite its name that file never
  gets above the horizon (see the README).

## How to take a clean one next time

1. Start the logger **at AOS**, not before, or pass `--minutes` so the window is the pass.
2. Have **exactly one** driver. `tracker.py` refuses to engage against another; that check
   exists because two drivers happened twice in one evening.
3. Hand-tuning is now fine — the offset is kept — but note the offset in the run, because the
   residual is then measured against centre + offset, not centre.

[offset]: the `reference_shack_track_offset_rule` memory
